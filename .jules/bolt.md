## 2024-11-10 - Resolve N+1 query problem with createMany
**Learning:** Found an N+1 query bottleneck in `server/controllers/pendingContactController.js` inside the `bulkApprove` method. The loop was sequentially querying for existing records via `findFirst` and creating new ones via `create` inside a loop. Additionally, noticed that using `createMany` could potentially lead to duplicate inserts if the target list itself contains duplicates.
**Action:** Used `findMany` to fetch all existing target records in a single query with an `in` filter, then iterated over the targets updating a shared `Set` of known phones to dedup the incoming list before using `createMany` to batch-insert the remaining new records in a single database operation, greatly reducing overhead and ensuring uniqueness.
