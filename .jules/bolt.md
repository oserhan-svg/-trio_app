## 2026-06-16 - Resolve N+1 Queries in Performance Controller
**Learning:** The `getConsultantPerformance` method in `server/controllers/performanceController.js` was looping over all consultants and firing 5 separate `prisma.*.count` queries for *each* consultant (e.g., Sale, Rent, New Portfolios, Interactions, Agenda tasks). If there are 50 consultants, this results in 251 concurrent DB queries, leading to N+1 bottlenecks.
**Action:** Replace `prisma.*.count` inside loops with batched queries using `prisma.*.groupBy` on the target table grouped by the consultant's foreign key (`assigned_user_id` or `user_id`). For relations that don't support direct `.groupBy` (like `interaction` via `client.consultant_id`), use `prisma.*.findMany` with select to fetch bare minimum nested references and aggregate locally.
