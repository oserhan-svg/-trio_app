## 2025-05-15 - [Component Hoisting & Callback Memoization]
**Learning:** Defining React components inside the render function of another component (e.g., SortHeader inside PropertyTable) is a performance anti-pattern. It causes the inner component to be re-created and thus re-mounted on every parent render, leading to significant UI flicker and overhead. Combined with memoized children (PropertyRow) receiving non-stable callbacks, this can completely negate React.memo's benefits.
**Action:** Always hoist sub-components to the module level or use useMemo if they need closure data (though props are preferred). Ensure all callbacks passed to memoized children are wrapped in useCallback, utilizing functional state updates (e.g., setState(prev => ...)) to minimize dependencies and maintain stable function identities.
